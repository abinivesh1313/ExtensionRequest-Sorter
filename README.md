# Extension Request Sorter

A console-based Python project for sorting student assignment-extension requests into:
- `within_policy`
- `needs_faculty_review`
- `needs_more_info`

**Important:** This tool does not approve or reject requests. It only extracts details and applies the department's stated rules. Faculty make every final decision.

## 1. Requirements
- Python 3.10 or newer
- A Google Gemini API key (for AI mode)
- Internet connection (for AI mode)

## 2. Setup on Windows PowerShell

```powershell
cd path\to\Extension_Request_Sorter
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
```

Open `.env` and replace the placeholder with your Gemini API key. Never upload `.env` to GitHub.

## 3. Run

```powershell
python main.py
```

For an offline demonstration without an API call:

```powershell
python main.py --offline
```

The offline mode uses conservative local keyword extraction. It is useful for checking the pipeline, but it is not a substitute for the Gemini extraction stage.

## 4. Input files
- `requests.csv`: at least 20 student-style requests; some are intentionally incomplete.
- `courses.csv`: valid semester course codes and names.

## 5. Output files
- `results.csv`: every request with course, days, reason, recommendation and privacy-safe summary. It does not contain the original request.
- `review_queue.csv`: requests not in `within_policy`, including the original text for authorised course faculty.
- `summary.txt`: aggregate counts by recommendation, reason and course. It contains no original request text.

## 6. Policy (implemented in Python)
1. If course or days is missing: `needs_more_info`.
2. If days is 3 or fewer and reason is medical, family or technical: `within_policy`.
3. Everything else: `needs_faculty_review`.

Change `MAX_DAYS_WITHIN_POLICY` in `main.py` if the department changes the threshold.

## 7. Privacy and validation
Python checks that a course code is present in `courses.csv` and appears in the student's original request. Python accepts days only if the student explicitly wrote the number (digits or supported number words). It does not calculate duration from dates or weekdays. The result summary is generated by Python from neutral fields, not copied from the LLM, so illness names, treatment details and people's names are not repeated.

The LLM is treated as an extractor only. The application parses the JSON, checks its shape and values, retries once after an invalid response/error, and uses a conservative local fallback if both attempts fail. The fallback is not guaranteed to understand every sentence; uncertain or missing fields should be checked by faculty.

## 10. Limitations
- The reason classifier can misinterpret ambiguous natural language.
- The fallback keyword rules are intentionally simple.
- The system cannot verify whether a student's explanation is true, whether evidence is genuine, or whether an exception is justified.
- Faculty must review all non-routine cases and make every final decision.
