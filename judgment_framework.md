# Judgment Framework

| Tool part | Cost of being wrong | Can it be verified without AI? | Who is accountable? |
|---|---|---|---|
| Course extraction | A request may be attached to the wrong course queue. | Yes. Python checks exact course codes against courses.csv and the original request. | Python performs the whitelist check; faculty verify unclear cases. |
| Days extraction | A wrong duration can change the recommendation. | Yes, when the student explicitly writes a number. Python searches for a written number and compares it with the LLM value. | Python validates explicit evidence; faculty handle ambiguous wording. |
| Reason extraction | A reason may be put in the wrong category and routed incorrectly. | Partly. Keywords can help, but meaning and context may be ambiguous. | LLM suggests a category; faculty review the original request. |
| Summary and privacy | Sensitive personal or health information could be exposed. | Yes, the output summary is generated by Python from neutral checked fields. | Python creates the neutral summary; project owner checks report handling and access. |
| Policy classification | A request may be routed to the wrong administrative group. | Yes. The policy is a deterministic set of Python rules and can be unit-tested. | Python applies the written rule; department owns the policy; faculty decide. |
| Truth of reason / supporting evidence | An inaccurate claim may be treated as credible. | No. The system cannot establish whether a personal explanation or evidence is genuine. | Faculty are accountable for reviewing evidence and making the final decision. |

## What Python cannot check
Python cannot determine whether a student's reason is true, whether a supporting document is genuine, or whether a compassionate exception is appropriate. Faculty cover this limitation by reviewing the original request and any required evidence. The tool never approves or rejects an extension.
